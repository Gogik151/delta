# Dildogram — копия Telegram (архитектура и спецификация)

> Документ описывает архитектуру, функциональность, API, базу данных, UI/UX и деплой для мессенджера уровня Telegram. Реализация кода в данном репозитории не включена — это стартовая спецификация и проектный каркас.

## Пошаговый план реализации

1. **Формирование требований и UX-вайрфреймов** — описать ключевые сценарии чатов/звонков/ботов.
2. **Определение архитектуры и инфраструктуры** — микросервисы, брокеры, сеть, observability.
3. **Проектирование базы данных** — ER-диаграмма, индексы, шардирование.
4. **Разработка API** — auth, чаты, сообщения, медиа, боты.
5. **Реализация realtime и присутствия** — WebSocket + presence service.
6. **Запуск медиа и звонков** — WebRTC + SFU.
7. **UI/UX и клиенты** — web + mobile + desktop.
8. **Безопасность и compliance** — TLS, rate limiting, аудит.
9. **Тестирование и нагрузка** — unit, integration, load tests.
10. **Деплой и масштабирование** — Kubernetes, CI/CD.

## 1. Общая концепция

**Dildogram** — современный мессенджер с фокусом на скорость, надёжность и безопасность. Поддерживает:

- личные чаты
- групповые чаты
- каналы
- ботов
- голосовые и видеозвонки
- обмен файлами
- реакции на сообщения
- поиск
- синхронизацию между устройствами

UX близок к Telegram, но без копирования дизайна и кода.

## 2. Платформы и стек

### Клиенты
- **Mobile:** Flutter (единый код для iOS/Android, быстрый UI, встроенные анимации)
- **Desktop:** Electron + React (быстрый кроссплатформенный клиент)
- **Web:** React + TypeScript (SSR опционально)

### Backend
- **API:** Go (gRPC/HTTP), высокая производительность
- **Realtime:** WebSocket + gRPC streams
- **DB:** PostgreSQL
- **Cache/Queue:** Redis
- **Message Broker:** Kafka
- **Media storage:** S3-совместимое (MinIO/AWS S3)
- **Search:** Elasticsearch/OpenSearch
- **Push:** FCM/APNS

## 3. Ключевая функциональность

### Авторизация
- вход по номеру телефона
- код подтверждения (SMS / email / push)
- двухфакторная аутентификация
- сессии на нескольких устройствах

### Сообщения
- текст, emoji, стикеры, GIF
- голосовые, видео
- файлы до **2–4 ГБ** (настраивается)
- редактирование, удаление
- пересылка, цитирование
- реакции

### Чаты
- личные
- групповые (до **200k** участников)
- каналы (публичные/приватные)
- роли: админ/модератор/участник
- закреплённые сообщения

### Звонки
- голосовые и видеозвонки
- WebRTC + SFU (Selective Forwarding Unit)
- шифрование
- переключение камер и микрофона

### Боты
- API для ботов
- команды
- кнопки
- inline-режим
- вебхуки

## 4. Безопасность

- TLS 1.3
- опциональное E2E-шифрование (секретные чаты)
- bcrypt/argon2 для паролей
- rate limiting
- защита от DDoS (WAF + CDN)
- аудит и логирование

## 5. Архитектура

### Микросервисы
- **Auth Service** — логин, сессии, 2FA
- **User Service** — профиль, контакты
- **Chat Service** — чаты, каналы
- **Message Service** — хранение сообщений
- **Media Service** — файлы, голос, видео
- **Call Service** — WebRTC/SFU
- **Bot Service** — API ботов
- **Search Service** — полнотекстовый поиск

### Реалтайм
- WebSocket Gateway
- gRPC внутри кластера

### Очереди
- Kafka для событий (message.created, user.online)
- Redis Streams для очередей

### Масштабирование
- горизонтальный scaling
- sticky sessions для WS
- Kubernetes + HPA

## 10. Best Practices

- gRPC между сервисами, REST для внешнего API.
- Все события через Kafka (event-sourcing light).
- Использовать idempotency keys для сообщений.
- TTL и архивирование для старых медиа.
- Шардирование сообщений по chat_id.

## 11. Возможные ошибки и решения

| Проблема | Причина | Решение |
|----------|--------|---------|
| Задержка сообщений | Перегрузка Kafka | Добавить партиции и consumer group |
| Потеря WS соединения | idle timeout | heartbeat/ping каждые 20-30 сек |
| Медиа не загружается | S3 timeout | retries + CDN |
| Поиск медленный | нет индексов | настроить OpenSearch |
| Нагрузка на БД | отсутствие шардирования | партиционировать таблицы |
